# 06 · 生命周期：知识会过期

## 6.1 为什么单独讲这件事

大多数知识库的死法不是「写错了」，而是「**曾经对，现在错，但没人知道它错了**」。

一条 2026 年 3 月正确的事实，在 2027 年被引用时，读者无从判断它是否还有效。
他只有两个选择：信它，或者不信整个库。两个都很糟。

## 6.2 三个字段管住这件事

| 字段 | 回答什么 | 谁强制 |
|---|---|---|
| `valid_from` | 从什么时候开始成立 | `instance` 模态必填 |
| `valid_until` | 到什么时间点不再成立 | 被 `supersedes` 替代时必填 |
| `review_at` | 什么时候该回头看一次 | 决策卡必填，到期报 warn |

`valid_until` 留空 = 长期有效，但**仍需复核**。留空是一种承诺，不是免检。

## 6.3 替代链：不改旧卡，只加新卡

**规则：已发布的结论不改写，只被替代。**

```
旧决策  status=superseded  valid_until=2026-04-01
  ↑ supersedes
新决策  status=accepted
```

机器会强制三件事（少一件就 violation）：

1. 被替代方必须写 `valid_until`
2. 被替代方若是决策卡，`status` 必须是 `superseded`
3. `supersedes` 两端必须是同类（决策替代决策，概念替代概念）

### 为什么不直接改旧卡

因为「当时为什么这么判」比「现在怎么判」更难重建。

示例库里 `D-20260110-新手训练路径` 写着：

> 四个月后发现这个判断对一个子集不成立：连粉粗细都无法稳定复现的人，
> 练注水时每次的粉层结构都不同，等于在噪声上练手法。

这句话的价值不在结论，在**「哪个前提塌了」**。直接改掉旧卡，这条信息就永久消失，
下次遇到同类问题还会再走一遍同样的弯路。

## 6.4 决策生命周期

| 状态 | 含义 | 机器要求 |
|---|---|---|
| `proposed` | 提了但没定 | 可无 `chooses`，但正文要有选项 |
| `accepted` | 已采纳 | 必须有 `chooses` + `decided_at` |
| `superseded` | 被新决策替代 | 必须被某个 `supersedes` 指向 + 有 `valid_until` |
| `rejected` | 提了但否了 | 保留 `rejects` 理由 |

`accepted` 不是终态。设一个 `review_at`，到期 `check` 会报 warn 提醒你回头看。
这不是形式主义：**没有复核日的决策，会悄悄变成「历史事实」被反复引用。**

## 6.5 阈值和指标要标来源

一条规则说「萃取率应在 18%–22%」，这个区间的合法性来自哪？

```markdown
calibrated_by: ["[[金杯准则]]"]
```

`calibrated_by` 指向标定集。它防止的失效是：**阈值被随手改，但没人知道改之前是多少、为什么改。**
标定集版本号变化时，所有依赖它的阈值都应该被重新审视——这条链要是断了，阈值就成了玄学。

## 6.6 例外：可以就地修改的情况

- 错别字、断链卡名（改名必须全局替换）
- 补 `anchors`、补 `definition` 的清晰度
- 修正明显的事实错误（如日期写错），且错误从未被别人引用

判断标准：**这条内容有没有被外部引用过？**
被引用过 → 走替代链；没被引用过 → 就地改。

## 6.7 巡检节奏

不需要复杂机制，一个每月五分钟的流程就够：

```bash
# 1. 谁该复核了
python3 vault/_kb/kb.py check | grep review_at

# 2. 谁的 valid_until 已经过去但没登记替代者
python3 vault/_kb/kb.py check | grep valid_until

# 3. 谁被替代了、新的是谁
python3 vault/_kb/kb.py lineage <卡名>
```

三条命令的输出就是本月待办。**没有输出的月份，不要伪造待办。**

## 6.8 验收判据

- [ ] 任意 `instance` 模态卡都有 `valid_from`，且关系值带 `(对象，截至 YYYY-MM)`
- [ ] 任意 `superseded` 决策都能用 `kb.py lineage` 查到「被谁替代」
- [ ] 任意阈值类卡都有 `calibrated_by`，且目标能指到一个有版本的标定集
- [ ] 所有 `accepted` 决策都有 `review_at`，且不是过去的时间
