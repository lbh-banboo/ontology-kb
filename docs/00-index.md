# 00 · 导航

这套仓库解决一个问题：**个人知识库怎么做才不会变成一个越堆越查不动的文件夹。**

答案不是「上一个更好的检索引擎」，而是把「知识之间的联系」从**检索问题**改回**数据问题**——
关系写进结构化字段，于是它可以被确定性查询、被回归测试、被提交前拦截。

## 三个不做什么

1. **不做自动关系抽取**。见 [09](09-failure-modes.md) F3。
2. **不做「大而全」的上位本体**。没有业务应用出现之前建全公司本体，是纯粹的负债。
3. **不做未经评测的准确率宣称**。本仓库的评测状态是 `PENDING`，README 里就这么写。

## 术语

| 词 | 含义 |
|---|---|
| TBox | 类型与关系本身（本仓库 `vault/_schema/ontology.md`） |
| ABox | 具体实例与实例间的事实（`vault/cards/**`） |
| typed 关系 | 写在 frontmatter 关系字段里、进图的边 |
| 提及 | 正文里的 `[[链接]]`，只供人读，不进图 |
| 占位节点 | 关系目标没有建卡，用纯文本表示，`check` 报 warn 但允许存在 |
| 守门 | 提交前强制校验，violation 拒绝提交 |
