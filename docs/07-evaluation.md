# 07 · 评测：没有冻结题集，就别声称准确率

## 7.1 先承认一件事

本仓库的评测状态是 **PENDING**。

不是「接近达标」，是**没有任何一轮跑完全部门槛**。README 里也这么写。
这看起来像自曝其短，实际是这套方法唯一能长期成立的前提：

> 一个不敢报告未达标的评测体系，最终会退化成「用来自我确认的仪式」。

## 7.2 四项门槛（示例值，不是行业标准）

| 指标 | 定义 | 示例门槛 |
|---|---|---|
| 引用覆盖率 | 冻结答案中有效来源支持的事实断言数 / 全部事实断言数 | ≥ 95% |
| Top5 召回 | 正样本中预登记卡全部出现在检索前五的题数 / 正样本题数 | ≥ 80% |
| 正确拒答 | 负样本中按冻结判分规则正确拒答或纠偏的题数 / 负样本题数 | ≥ 85% |
| 推理违规 | 出现「反推成立」「非传递关系多跳」等违规的次数 | = 0 |

**门槛值是示例，不是普适标准。** 引用覆盖率门槛高、推理违规必须为 0，这两条是结构性的；
召回率和拒答率取决于你的库服务于什么场景。

## 7.3 为什么必须有「正确拒答」

只测「答对了多少」，系统会奖励**什么都答**。

一个对所有问题都给出合理答案的系统，在只有 60% 问题有答案的库里，
看起来准确率很高，实际上 40% 的输出是编的——而编造在知识库里是最贵的错误，
因为它会被下游当成事实继续引用。

负样本要包含三类：

| 类型 | 例 | 正确行为 |
|---|---|---|
| 库里确实没有 | 「这张卡引用了哪篇论文？」（anchors 只写了标准号） | 明确说「库内无此信息」，不猜 |
| 有提及但无关系 | 「A 依赖 B 吗？」（只在正文提过） | 说「无此关系登记」，不推断 |
| 前提已失效 | 「现在用的是哪个方案？」（旧决策已 superseded） | 指出替代链，不用旧答案 |

第二类是本仓库最容易被忽略的：见 [04](04-body-vs-relation.md)。

## 7.4 冻结题集怎么建

### 规模

首批 **100–200 条**。少于 100 条，一个题的差异就能让指标跳 1%，看不出趋势；
多于 200 条，你会因为维护成本而停止更新，最后变成一次性考试。

### 冻结的含义

题集一旦冻结，**改题必须留痕**：

```markdown
| 版本 | 日期 | 改了什么 | 为什么 |
|---|---|---|---|
| v1 | 2026-01-10 | 首版 120 题 | — |
| v2 | 2026-04-01 | Q19 事实前提变更（旧结论已 superseded） | 不是答案变了，是世界里的事实变了 |
| v3 | 2026-04-01 | Q8 题干澄清 | 原题干有歧义，两个标注者理解不同 |
```

三种改动要严格区分，很多评测体系在这里作弊：

| 改动 | 性质 | 是否合法 |
|---|---|---|
| 答案随实现调整 | 改判分标准 | ❌ 禁止 |
| 题干澄清（原题干有歧义） | 修题 | ✅ 但要留痕 |
| **事实前提变更**（旧结论被替代） | 题目本身过期 | ✅ 必须留痕，且要写明「不是随答案改题」 |

第三行是最容易滑向作弊的地方：一个结论被替代后，旧题的「正确答案」变了。
这时改题是正当的，但**必须显式登记「前提变了」**，否则外人无法区分
「题目过期」和「答案调不动就改题」。

### 每道题要有什么

```json
{"q": "Q3 金杯准则约束了谁", "cmd": "constraints", "card": "金杯准则",
 "expect": ["它约束谁", "萃取率", "D-20260401-新手训练路径改版"],
 "forbid": []}
```

- `cmd` 限定走哪条查询路径（本仓库：`ask` / `impact` / `constraints` / `lineage` / `chain`）
- `expect` 是**必须出现**的字符串，`forbid` 是**必须不出现**的
- 正样本用 `expect`，负样本用 `forbid` + `expect: ["（库内无此关系登记）"]`

`forbid` 是这套题集里最有用的字段：它能把「禁止的行为」写成断言，
而多数评测只写「期望的输出」。

## 7.5 跑评测

```bash
python3 vault/_kb/kb.py test                  # 默认读 vault/_kb/tests.json
python3 vault/_kb/kb.py test path/to/other.json
```

输出：

```
[PASS] Q1 注水手法由哪个工具实现 ask 注水手法
[FAIL] Q8 替代链：旧决策被谁替代 lineage D-20260110-新手训练路径 缺=['valid_until=2026-04-01']
断言 9/10 PASS
```

`[FAIL]` 行会直接告诉你缺哪个字符串——这是刻意设计，因为**只说「失败了」的评测没法修**。

### 卡名解析失败要单独报

如果一条题因为**卡名不存在**而失败，它和「关系错了」是两类问题。
本仓库的做法是把它们分开打印（`其中 N 条因卡名不存在而失败`），
否则卡改名之后，你会以为关系大面积变坏。

## 7.6 阈值怎么标定

不要预设阈值。顺序是：

1. 先跑一轮，拿到所有题的原始结果
2. 人工标注其中 30–50 条，建立「人工判定集」
3. 用人工判定集反推：什么阈值能让机器结果与人工判定的一致性最高
4. 把这个阈值写进指标卡的 `calibrated_by`
5. 标注集本身要带版本号，改了要重标

跳过第 2 步直接定阈值，得到的数字只反映你的期望，不反映系统的能力。

## 7.7 别做的事

| 反模式 | 后果 |
|---|---|
| 按实现调整 `expect` | 指标永远 100%，永远无意义 |
| 只跑一次就宣布达标 | 看不到回归，改坏了也不知道 |
| 题集只有正样本 | 系统会学会乱答 |
| 用同一批题既调优又验收 | 过拟合，换批题就崩 |
| 门槛没达标就写「已通过」 | 这份诚实是库最值钱的资产，别为好看改口 |

## 7.8 验收判据

- [ ] 题集 ≥ 100 条，含正负样本
- [ ] 每条题有 `cmd` / `card` / `expect`，负样本有 `forbid`
- [ ] 改题记录表存在，且区分了「改判分 / 修题 / 前提变更」
- [ ] 四项门槛各有明确数字，未达标的项**如实写出**
- [ ] 门槛值能指到 `calibrated_by` 的标定集
